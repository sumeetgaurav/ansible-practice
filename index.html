The basics

What is Ansible?

Ansible is an open-source automation tool for configuration management, application deployment and infrastructure tasks. You describe the desired state of your servers in a playbook, and Ansible makes it happen, safely and repeatedly.

🚫

Agentless

Nothing to install on target servers. Ansible connects over SSH and runs the work.

📝

Simple YAML

Playbooks are human-readable, so even beginners can understand what they do.

🔁

Idempotent

Run it once or ten times, and the result is the same. It only changes what needs changing.

📈

Scalable

Manage 2 servers or 2,000 with the same playbook and a single command.

Building blocks

Key Concepts

Five terms cover most of what you'll use day to day.

TermMeaningExample
Control nodeThe machine where Ansible is installed and run from.Your Ubuntu EC2 instance
Managed nodesThe servers Ansible configures.worker-node-1, worker-node-2
InventoryA file listing managed nodes, grouped.hosts.ini
ModuleA small tool that does one job.apt, copy, service, ping
TaskOne call to a module with arguments.Install the package tree
PlaybookA YAML file with plays, which contain tasks.install.yml
Under the hood

How It Works

From your command to the finished change, in four steps.

1

Read inventory

Finds which servers belong to the target group.

2

Connect via SSH

Logs in using your key and the host key it trusts.

3

Run modules

Copies small scripts over, runs them, then removes them.

4

Report results

Shows ok, changed or failed for each host.

See it in action

Inventory & Playbook

A tiny inventory and a playbook that installs a few packages on every server.

hosts.ini
[servers]
worker-node-1 ansible_host=44.252.108.50
worker-node-2 ansible_host=34.219.231.41

[servers:vars]
ansible_user=ubuntu
ansible_ssh_private_key_file=~/.ssh/my-key.pem
install.yml
- name: Install Packages
  hosts: servers
  become: yes   # use sudo

  vars:
    packages:
      - tree
      - zip
      - jq

  tasks:
    - name: Install packages
      apt:
        name: "{{ packages }}"
        state: present
        update_cache: yes
Cheat sheet

Commands You'll Use Daily

Keep these handy while you practice.

CommandWhat it does
ansible --versionShows the version and which config file is in use
ansible -i hosts.ini servers -m pingTests SSH connectivity to every host in the group
ansible-inventory -i hosts.ini --listDisplays how Ansible reads your inventory
ansible-playbook -i hosts.ini install.ymlRuns a playbook
ansible-playbook install.yml --checkDry run: shows what would change, changes nothing
ansible-vault encrypt secrets.ymlEncrypts a file holding passwords or keys
ansible-playbook -i hosts.ini play.yml -vvvVerbose output for debugging
Good habits

Best Practices

Small choices that keep your automation clean and safe.

✔ Name every task clearly
✔ Use modules instead of raw shell commands
✔ Encrypt secrets with Ansible Vault
✔ Test with --check first
✔ Keep playbooks in Git
✔ Use 2-space indentation, never tabs
